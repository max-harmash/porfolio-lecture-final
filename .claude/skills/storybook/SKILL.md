# Storybook у цьому проєкті

Storybook показує компоненти дизайн-системи окремо від сайту. Студент — нетехнічний дизайнер-початківець. Пояснюй простими словами, не вимагай знати API Storybook, після кожного кроку коротко кажи, що зроблено.

## Перед початком

1. Прочитай `CLAUDE.md` у корені: стек, токени, список компонентів, правила.
2. Токени оголошені в блоці `@theme` у `src/app/globals.css`. Це єдине джерело значень. Шрифти підключені в `src/app/fonts.ts` через `next/font`.
3. Перевір, чи Storybook уже є: тека `.storybook` і скрипт `storybook` у `package.json`.

## Токени системи

- Кольори: `canvas` (фон сторінки), `surface` (картки й поля), `line` (декоративні лінії й рамки карток), `accent`, `ink`, `ink-muted`, `danger` (помилка). Класи: `bg-canvas`, `bg-surface`, `border-line`, `bg-accent`, `text-ink`, `text-ink-muted`, `text-danger`, `border-danger`.
- Межа поля форми й кнопки без заливки: `ink-muted` (контраст не менше 3:1), не `line`.
- Радіуси: `rounded-control` (кнопки, поля), `rounded-card` (картки). У цьому проєкті обидва дорівнюють 0: макет прямокутний.
- Розміри тексту: `text-caption`, `text-body`, `text-lead`, `text-heading`, `text-display`. У цьому проєкті ще `text-title`, `text-button`, `text-label`, `text-hand`; кожен розмір несе висоту рядка, а де роль однозначна, ще трекінг і жирність.
- Шрифти: `font-mono` (Martian Mono), `font-sans` (Geologica), `font-hand` (Caveat).
- Відступи: тільки 8, 12, 16, 24, 32 px, тобто числа 2, 3, 4, 6, 8 у класах (`p-2`, `gap-4`).
- Особливості цього проєкту:
  - на `accent` текст лише `ink` (5.7:1); білий на `accent` дає 3.3:1;
  - `accent` як колір дрібного тексту на `canvas` дає 3:1, тобто нижче за 4.5:1;
  - `ink-muted` на `line` дає 4.2:1, тож для тексту ці кольори не поєднуй;
  - допоміжні класи: `aspect-cover` (обкладинка картки), `bg-grid` (фонова сітка), `border-thin` (рамка 1.5px).

Усе, що є в історіях, документації й компонентах, будується тільки з цього. Заборонено: hex і rgb, стандартні класи Tailwind поза системою (`bg-blue-600`, `text-sm`, `rounded-lg`), значення в квадратних дужках (`p-[13px]`). Якщо історії чи документації потрібен елемент, якого немає в системі, не вигадуй його: перелічи, чого бракує, і запитай студента.

## Налаштування, якщо Storybook ще немає

1. У корені проєкту запусти `npm create storybook@latest -- --features docs a11y`. Потрібен Node.js 20 або новіший. Для Next.js Storybook радить фреймворк `@storybook/nextjs-vite`. Обираються лише docs (документація) і a11y (доступність). НЕ використовуй прапорець `--yes`: він вмикає всі можливості, включно з тестами. Якщо ініціалізація все одно питає, що додати, обери лише docs і a11y, а варіант Recommended не вибирай. Скажи студенту, що саме додалося.
2. У `.storybook/preview` імпортуй головний файл стилів з токенами (`import '../src/app/globals.css';`) і додай шрифти: декоратор, що обгортає історію класами змінних шрифтів з `src/app/fonts.ts`. Без цього компоненти в історіях виглядають голими.
3. Якщо аддона доступності ще немає: `npx storybook add @storybook/addon-a11y`.
4. У `.storybook/main` НЕ додавай `staticDirs: ['../public']`. Storybook збирається в `public/storybook`, і з цим рядком збірка падає з помилкою `ERR_FS_CP_EINVAL`. Приклад з документації Storybook містить цей рядок: якщо він є в конфігу, прибери його й скажи студенту.
5. Приклади історій, які створила ініціалізація (Button, Header, Page), не належать проєкту. Після того як готова наша історія кнопки, прибери їх і скажи студенту.
6. Стартові стилі й тема `create-next-app`: змінні `--background` і `--foreground`, медіазапит темної теми, шрифти Geist. Якщо вони заважають системі токенів (перебивають `canvas` та `ink`, підміняють шрифт), прибери їх і скажи студенту, що саме видалено. Якщо не заважають, не чіпай.
7. Не вмикай і не підключай те, що ініціалізація пропонує додатково: Vitest, Playwright, MCP-аддон (`@storybook/addon-mcp`), Chromatic, команду `storybook skills setup`. Якщо вони з'явилися в проєкті, скажи студенту й запитай, що робити.
8. У `package.json` мають бути скрипти: `storybook` (запуск, `npm run storybook`) і скрипт збірки для публікації (див. нижче).

## Історія компонента: одна на компонент

Правило курсу: ОДНА історія на компонент, з панеллю Controls. Не створюй окремих історій Default, Hover, Focus, Disabled.

- Файл `<Компонент>.stories.tsx` лежить поруч із компонентом.
- `title` історії пиши латиницею: `Components/Button`. Кирилицю в `title` не став: з неї виходять кириличні ідентифікатори історій. Українські пояснення клади в опис компонента.
- Перемикачі (`argTypes`) покривають усі варіанти й стани компонента: варіант і розмір через `select`, `disabled` через `boolean`. У поля форми додатково помилка (`boolean`) і текст помилки. Значення за замовчуванням стоять в `args`.
- Стани hover, focus і disabled стилізуються в самому компоненті токенами. Історія їх лише показує, свої стилі в ній не пишуться.

Приклад (кнопка):

```tsx
// Тип Meta і StoryObj бери з пакета фреймворку, який стоїть у .storybook/main
import type { Meta, StoryObj } from '@storybook/nextjs-vite';
import { Button } from './Button';

const meta = {
  title: 'Components/Button',
  component: Button,
  tags: ['autodocs'],
  argTypes: {
    variant: { control: 'select', options: ['primary', 'secondary'] },
    size: { control: 'select', options: ['md', 'lg'] },
    disabled: { control: 'boolean' },
  },
  args: { children: 'Написати мені', variant: 'primary', size: 'md', disabled: false },
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

export const Playground: Story = {};
```

Hover і focus. За замовчуванням показуй їх справжніми: компонент в історії живий, студент може навести мишу й пройти клавішею Tab. Це основний спосіб, і він працює завжди. Перемикача hover і focus у панелі Controls немає. Якщо студент хоче перемикач, спробуй аддон `storybook-addon-pseudo-states` (`npx storybook add storybook-addon-pseudo-states`): його перемикач живе в тулбарі Storybook, а не в Controls, а значення за замовчуванням задає `parameters.pseudo`. Спробуй і не стверджуй, що він працює, поки не перевірив у браузері. Якщо не вийшло, лиши справжні hover і Tab та скажи про це студенту. Окремі історії по станах як обхід не створюй.

## Документація компонента

Кожен компонент має сторінку docs. Вона потрібна студенту й агентам: за нею Claude розуміє, що це за елемент і як його підключити.

Структура, однакова для всіх компонентів:

- короткий опис: що це і навіщо;
- параметри (пропси) і значення за замовчуванням;
- варіанти і стани;
- токени, які використовує компонент, за іменами;
- коли використовувати, а коли ні;
- як брати в код (короткий приклад).

Зверху опис усього перерахованого, під ним сам компонент з панеллю Controls.

Як зробити: тег `autodocs` у `tags`; JSDoc-коментарі над компонентом і над кожним пропсом; довший опис у `parameters.docs.description.component`. Коли JSDoc не вміщає структуру, зроби MDX-файл: `<Meta of={...} />`, `<Canvas of={...} />`, `<Controls />` (імпорт з `@storybook/addon-docs/blocks`).

Токени називай за іменами: `accent`, `ink-muted`, `rounded-control`. Значень (hex, px) не пиши ні в `.tsx`, ні в `.mdx`: вони живуть тільки в `@theme`. Опис пиши так, щоб агент, який прочитав лише його, міг правильно взяти компонент.

## Після кожної зміни компонента

Змінив пропси, варіанти, стани чи токени компонента: у тому ж кроці оновлюй історію (`argTypes`, `args`) і docs. Новий варіант без перемикача в Controls і без рядка в документації — не доведена до кінця робота. Додав новий компонент: створи історію й docs, а студенту скажи, що розділ «Компоненти» в `CLAUDE.md` треба оновити, і зроби це, якщо він погодиться.

## Сторінка токенів (тільки за запитом)

Якщо студент просить сторінку «Токени»: MDX-файл з блоками `ColorPalette` і `ColorItem` (кольори) та `Typeset` (шкала шрифтів) з `@storybook/addon-docs/blocks`. Для відступів готового блока немає, зроби власну таблицю в MDX. Значення не вписуй: у `colors` передавай змінні, наприклад `var(--color-accent)`.

## Збірка для публікації разом із сайтом

Роби це тільки на прохання студента.

1. Storybook збирається в `public/storybook`: `storybook build -o public/storybook`, команда лежить у скрипті `package.json`. Тоді Next.js віддає його за адресою сайту з `/storybook/`.
2. Збірка Storybook має йти раніше за збірку сайту. Приклад скрипта `build`: `storybook build -o public/storybook && next build`. Скажи студенту, що саме ти змінив.
3. Тека `public/storybook` — результат збірки, вручну її не редагуй. Обов'язково додай `public/storybook` у `.gitignore`. Без цього збудований Storybook потрапляє в автоскан файлів Tailwind v4: зʼявляються зайві утиліти, збірка сповільнюється, а в Git потрапляють величезні зміни. Vercel збирає цю теку сам під час деплою.
4. Працюй в окремій гілці. Збери проєкт локально (`npm run build`) і перевір, що файл `public/storybook/index.html` існує.
5. Публікація, пуш і перевірка деплою — робота скіла `vercel`, спершу превʼю. Сам нічого не пушиш і не деплоїш.

## Як перевірити результат

1. Запусти `npm run storybook` і скажи студенту адресу (зазвичай `http://localhost:6006`).
2. Скажи, що перевірити: перемикачі Controls змінюють компонент; наведення миші; Tab показує контур фокусу; вкладка Docs має всі пункти структури; панель Accessibility не показує нових Violations.
3. Панель Accessibility — додаткова перевірка, не вердикт: контраст кольорів студент звіряє у WebAIM Contrast Checker.
4. Не стверджуй, що все виглядає правильно, якщо сам цього не бачив: попроси студента подивитись і описати.
5. `npm run build` має проходити без помилок.

## Чого цей скіл не робить

- Не публікує і не пушить (це скіл `vercel`).
- Не підключає MCP-сервери (Storybook MCP, Vercel MCP).
- Не створює окремих історій по станах.
- Не змінює токени в `@theme` заради історії чи документації.
- Не ставить Vitest, Playwright, Chromatic і MCP; не додає тести й візуальні регресійні перевірки.
- Скіл це інструкція в контексті сесії, а не примус: Claude може відступити від неї, тому результат перевіряй сам. Розсинхрон шукай запитом із розділу «Три способи побачити розсинхрон» у занятті 6.
